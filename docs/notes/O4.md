# O4 — shared API services, HR route freeze, lookups, workspace seam, search, stubs

Notes worth carrying into CLAUDE.md / the model doc once the build integrates.

- **Manila-pinned calendar keys live in `api/src/shared/day.ts`** (`manilaDayKey`,
  `manilaMonthKey`). Deep links and forecast columns bucket on these, never on
  the host clock. Numbering keeps its local-getter `{YYYY}/{MM}`.
- **`activityWhere()` in `shared/activities.ts` is the one rule** for which
  sales activities a query means (inclusive `lte`, 14-day default, window
  dropped for a record, newest first for a record). `sales.ts GET /activities`
  is to spread it (P3); the calendar verification asserts it (P5).
- **`quotationValue()` in `shared/pipeline.ts` is the one value rule**: the
  APPROVED revision's total, else the highest-numbered revision's, else 0.
- **G-CHAIN figures are decided once in `shared/chain.ts`** — `stockOnHand()`
  and `chainOverview(me)`; `GET /api/gchain/overview` serves the dashboard. A
  tile the caller cannot open is `null`, never 0.
- **Calendar hand-offs are pure** (`shared/calendar-links.ts`): `.ics` with a
  stable UID and a SEQUENCE, a pre-filled Google Calendar URL, and
  `parseGoogleLink` sorting a pasted Meet link from a Calendar event link.
  G-Core holds no Google credentials. `env.appUrl` is what those links print.
- **`attendanceDay(date)` in `shared/hr.ts` IS the HR dashboard.** The route
  calls it and nothing else; `verify-hr.ts` asserts the two are byte-identical.
  `pendingApprovals` now counts pending evaluations too.
- **`myEmployee(userId)` is exported from `shared/hr.ts`**, selects no pay data.
- **HR lists are Settings, whitelisted by route**: `GET/PUT /hr-settings/lists/:key`
  for `hr.clearanceChecklist` and `hr.evaluationCriteria`, each with its own zod
  row schema; GET returns `{ key, rows }`, PUT takes `{ rows }`. `settingList<T>()`
  reads them.
- **`GET /users/lookup?q=&holding=`** is the people picker — `authenticate` only,
  names only, above `/:id`. `holding=` means role or ALLOW override minus DENY,
  and super admins, matching `can()`.
- **`registerSchedule(fn)` in `routes/workspace.ts`** is the seam for "today":
  Meetings and the Academy register providers from their own modules; a verify
  script that expects a row must import that module.
- **Search providers may declare `permission: string[]` and `ownWhere(user)`** —
  the own-scope narrowing is applied only when the caller holds none of the
  provider's non-`view_own` keys. Lead/quotation/costing/job providers do this.
  The approval fallback link is `/my-work`.
- **`redact()` now strips** `dailyRate, burdenMultiplier, sssNo, philhealthNo,
  pagibigNo, tin` — the Phase 6 promise in audit.ts finally kept.
- **My Work's "today" window is local midnight to local midnight** on the
  server, a timestamp window. HR's `dayKey()` is a key for `@db.Date` columns
  (UTC midnight of the local date) and would have placed the boundary at 08:00
  Manila — so the plan's "computed with dayKey()" was read as its intent.
