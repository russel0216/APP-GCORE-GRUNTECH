## Seed

- **Industries** — five system rows (HI, BI, UI, GI, SI), same contract as cost
  categories: `create { sortOrder, isSystem: true }`, `update { isSystem: true }`.
- **Numbering loop** — `create` spreads `dt.defaults ?? STOCK_NUMBERING`
  (`{PREFIX}-{TYPE}-{YYYY}-{SEQ}`, padding 4, YEAR, GLOBAL); `update` is still
  `{ label }` only, so an administrator's configured pattern is never
  overwritten. Types carrying their own default print in the summary line.
- **expectedClosing backfill** — one `$executeRawUnsafe` after numbering. The
  plan's SQL gained `AND l."expectedClosing" IS NOT NULL`: same semantics (fills
  nulls only) but the update count it prints is then honest, and the second
  run is silent rather than re-writing null over null.
- **Workflows** — `cash_advance` (supervisor → finance), `job_order` (service
  manager), `clearance` (supervisor → finance → HR), `evaluation` (HR →
  executive), `training_certification` (HR). Meetings deliberately have none.
- **`backfillPositions()`** — after Departments. Idempotent: only employees with
  `positionId IS NULL` and non-empty `position` text; grouped by trimmed,
  case-folded title; matched to an existing `Position` by title (insensitive)
  or created with `code: nextNumber('position', tx)`, the first holder's
  spelling, the department only when every ACTIVE holder shares one, and
  `authorisedHeadcount` = the number of active holders. Prints
  `· Plantilla: linked N employee(s) to M position(s)` only when it did
  something, so a second seed stays silent. Package A may swap this for
  `shared/plantilla.ts` later (merge-tail item 80).
- **Settings, create-only** — `hr.clearanceChecklist` (seven lines across the
  five `ClearanceArea` values), `hr.evaluationCriteria` (QUAL, PROD, KNOW,
  ATT, TEAM, INIT for BOTH; LEARN for TRAINEE; all weight 1),
  `academy.rules`. `hr.rules` `create` gains `probationMonths`,
  `evaluationMilestoneMonths`, `evaluationNoticeDays`, `ratingScale`,
  `ratingLabels`. The seed does not spread `DEFAULTS` from `shared/hr.ts`
  (it never did — it lists the values); existing installs get the new keys
  from `DEFAULTS` through `hrSettings()`, exactly as area-hr §7 item 13 says.
- **Roles** — every pair below is never-offered, so the next seed grants it
  to existing roles without touching a revocation. New system role `trainer`.

## Workflow audit

`TYPICAL_REQUESTER` gains `cash_advance`, `job_order`, `clearance`,
`evaluation`, `training_certification`. New check: an `HR` step on a document
HR sometimes raises, with exactly one HR holder, is reported as the HR-typed
version of the single-holder fault. Expected after seeding:
`clearance 1. supervisor → 2. finance → 3. hr`,
`evaluation 1. hr → 2. executive`, `training_certification 1. hr`.

## Not run here

The seed and the audit were not run — the schema push is another package's
step and the gate runs them. `nextNumber('position', tx)` is called with the
seed's own transaction client against the rewritten `numbering.ts` signature
`(documentType, tx, ctx)`.
